# horizon-news-bot

Telegram-бот, который несколько раз в сутки присылает новости на русском о том,
что изменилось и появилось в [Horizon](https://github.com/horizon-rust/horizon) —
Minecraft: Java Edition, переписанном на Rust.

Своего сервера у бота нет. Его по расписанию запускает GitHub Actions: бот делает
один проход и завершается.

## Откуда новости

Только из уже вышедших релизов `horizon-rust/horizon`: Nightly-сборок игры и релизов
лаунчера. Открытые pull request'ы, планы и слухи бот не публикует. У каждого пункта
стоит ссылка на его pull request, у каждого сообщения — ссылка на релиз.

## Как проходит запуск

1. `check` — бот спрашивает у GitHub список релизов. Если нового нет, запуск на этом
   заканчивается за пару секунд.
2. Из новых релизов бот берёт пункты под заголовками (`New`, `Fixed` и другими),
   убирает уже отправленные и сворачивает однотипные строки в одну.
3. `post` — бот запускает `llama-server` с открытой моделью, переводит пункты на
   русский и отправляет сообщение в Telegram.
4. Что отправлено, бот записывает в `state.json` в ветке `state`.

Игровой релиз идёт отдельным сообщением. Все новые релизы лаунчера за один запуск
объединяются в одно.

## Перевод и защита от искажений

Переводит открытая модель Gemma 4 E4B (Apache-2.0), её исполняет
[llama.cpp](https://github.com/ggml-org/llama.cpp) прямо на раннере. Ключи и платные
сервисы не нужны.

Модель переводит по одной строке и не видит ни ссылок, ни номеров pull request'ов —
их подставляет код. Перевод принимается, только если он:

- одна законченная строка, в основном по-русски, не намного короче и не намного
  длиннее оригинала;
- содержит те же числа в том же порядке, что и оригинал;
- сохранил идентификаторы кода (`key.toggleGui`, `toast_add`, `/gamemode`,
  `minecraft:stone`) буква в букву;
- не добавил ссылок и упоминаний, которых не было в оригинале.

Иначе пункт уходит на английском, как в оригинале.

## Чего бот не гарантирует

- Перевод делает небольшая модель. Проверки ловят искажённые числа и идентификаторы,
  но не корявую фразу. Первоисточник всегда по ссылке рядом.
- Текст пунктов берётся из релизов Horizon как есть. Бот доверяет этому репозиторию:
  что там написано, то и будет опубликовано.
- Если сеть оборвалась уже после того, как Telegram принял сообщение, бот об этом не
  узнает и в следующий запуск пришлёт это одно сообщение ещё раз. Во всех остальных
  случаях оборванная сводка продолжается с того места, где остановилась.

## Расписание

09:07, 13:07, 18:07 и 22:07 по Минску (`.github/workflows/news.yml`). GitHub может
задержать запуск на несколько минут. Запустить вручную:

```sh
gh workflow run news.yml
```

## Настройка

Секреты репозитория:

| Секрет | Что это |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | чат, куда бот пишет |

Чтобы бот мог написать человеку в личку, тот должен один раз нажать у бота `/start`.

Версии llama.cpp и модели закреплены в `news.yml` вместе с контрольными суммами.

## Разработка

```sh
cargo test
cargo clippy --all-targets -- -D warnings

# Посмотреть, что бот отправил бы сейчас, ничего не отправляя и не меняя:
cargo run -- post --dry-run --state /tmp/state.json
```

Push в `main` запускает `build.yml`: тесты, сборка статического бинарника, подпись
его происхождения и публикация в релизе `bot`. `news.yml` берёт бинарник оттуда и
перед запуском проверяет подпись: файл, который собрал не `build.yml` из ветки
`main`, выполнен не будет.

| Файл | За что отвечает |
| --- | --- |
| `src/github.rs` | запрос релизов |
| `src/parse.rs` | разбор заметок релиза на пункты |
| `src/digest.rs` | что считать новостью, группировка, сворачивание |
| `src/translate.rs` | запуск `llama-server`, проверка перевода |
| `src/telegram.rs` | вёрстка сообщения и отправка |
| `src/state.rs` | память между запусками |

Если в публичном репозитории 60 дней нет активности, GitHub отключает расписание и
присылает письмо. Коммиты бота в ветку `state` считаются активностью, так что это
возможно, только если Horizon надолго перестанет выпускать релизы.
